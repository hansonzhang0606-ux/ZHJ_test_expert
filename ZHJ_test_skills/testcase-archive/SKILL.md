# testcase-archive Skill

## 目标

在 `md-to-xmind-testcase` 生成详细测试用例、人工完成评审并保存 `*_测试用例_详细版reviewed.xmind` 后，自动执行以下操作：

1. 解析 AI 生成版与人工评审版的 XMind 文件
2. 自动对比差异（新增 / 删除 / 修改 / 位置调整）
3. 进行测试用例质量分析
4. 生成差异报告和质量分析报告
5. 将最终用例合并入库到知识库
6. 更新 `INDEX.md` 和 `EVOLUTION_LOG.md`

> 在智慧记运营八阶段工作流中，本 Skill 对应第⑤步：AI 对比入库（`05`）。

---

### 输出

|------|------|
| `*_测试用例_对比差异报告.md` | 新增 / 删除 / 修改 / 位置调整清单 |

## XMind 解析规则

### 文件结构

XMind 文件本质为 ZIP 压缩包，核心数据位于：

```
<文件名>.xmind
├── content.json      # 主要数据（优先读取）
├── content.xml       # 兼容格式（如 content.json 不存在则读取）
├── manifest.json
└── resources/        # 图片等资源（解析时忽略）
```

### 节点解析

1. 读取 `content.json`，取第一个 sheet 的 `rootTopic`
2. 递归遍历 `rootTopic` → `children.attached`
3. 提取每个节点的：
   - `title` 或 `attributedTitle`（兼容富文本标题）
   - `markers`（优先级标记等）
   - 子节点列表
4. 识别测试用例节点：节点标题匹配 `P\d+[_-]` 前缀，或子节点包含「测试步骤 / 预期结果 / 前置条件」
5. 提取测试用例字段：
   - 用例名称
   - 优先级（从 markers 或「优先级」子节点提取）
   - 前置条件
   - 测试步骤
   - 预期结果

### 无需人工标记

> 评审版 XMind **不再强制要求人工标记**。
> AI 通过对比两个版本的节点树，自动识别新增、删除、修改和位置调整。

---

## 自动对比规则

### 节点匹配策略

1. **精确匹配**：规范化后的用例名称一致
   - 移除 `P\d+[_-]` 前缀
   - 统一「货号/款号」「货号 / 款号」→「款号」
   - 移除数字、空格、标点
2. **模糊匹配**：精确匹配失败时，综合用例标题、测试步骤、预期结果的语义相似度进行匹配
3. 匹配阈值：语义相似度 ≥ 0.6

### 差异分类

| 类型 | 定义 |
|------|------|
| **新增** | reviewed 中存在、ai 版本中不存在的用例节点 |
| **删除** | ai 中存在、reviewed 中不存在的用例节点 |
| **修改** | 名称匹配成功，但优先级、前置条件、测试步骤、预期结果任一字段发生变化 |
| **位置调整** | 同一用例在不同版本中的父节点或层级发生变化 |
| **未变更** | 名称和内容完全一致的用例 |

### 字段级变更检测

对修改用例，进一步检测：

- 优先级变化
- 前置条件增删
- 测试步骤增删 / 文本变化
- 预期结果增删 / 文本变化

---

## 质量分析指标

| 指标 | 计算方式 | 说明 |
|------|---------|------|
| **覆盖率** | (未变更 + 修改) / AI 生成总数 | AI 生成用例中被保留或适配的比例 |
| **严格准确率** | 未变更 / AI 生成总数 | 文本完全一致、无需修改的用例比例 |
| **语义准确率** | 语义相似度 ≥ 0.7 的修改用例 / AI 生成总数 | 语义层面基本正确的用例比例 |
| **可执行率** | 含测试步骤且含预期结果的评审用例 / 评审后总数 | 评审用例的可执行比例 |
| **冗余率** | 重复或低价值用例 / 评审后总数 | 人工判断或启发式检测 |
| **场景遗漏率** | 新增用例 / 评审后总数 | 人工补充场景占最终用例比例 |
| **多余生成率** | 删除用例 / AI 生成总数 | AI 生成但被删除的用例比例 |
| **修改率** | 修改用例 / AI 生成总数 | AI 生成但被修改的用例比例 |
| **通过率** | (未变更 + 修改) / AI 生成总数 | AI 生成用例通过评审保留的比例 |

### 语义相似度计算

综合以下三方面：

1. 用例标题语义相似度（移除数字、标点后比较）
2. 测试步骤语义 token 集合的 Jaccard 相似度
3. 预期结果语义 token 集合的 Jaccard 相似度

## 处理流程

### 步骤 1：解析两个 XMind 文件

```python
# 伪代码
ai_xmind = load_xmind('*_测试用例_详细版_v1.0-ai.xmind')
reviewed_xmind = load_xmind('*_测试用例_详细版reviewed.xmind')

ai_cases = extract_test_cases(ai_xmind)
reviewed_cases = extract_test_cases(reviewed_xmind)
```

### 步骤 2：自动对比并分类

```python
result = compare_cases(ai_cases, reviewed_cases)
# result.added, result.deleted, result.modified, result.unchanged
```

### 步骤 3：生成差异报告

输出 `*_测试用例_对比差异报告.md`，包含：

- 概览统计
- 新增用例清单
- 删除用例清单
- 修改用例清单（含字段级变更点）
- 位置调整说明（如适用）

### 步骤 4：生成质量分析报告

输出 `*_测试用例_质量分析报告.md`，包含：

- 统计概览
- 质量指标表格
- 语义相似度说明
- 质量评估结论
- 改进建议

### 步骤 5：合并入库

1. 将 `*_测试用例_详细版reviewed.xmind` 复制到 `knowledge-base/testcases/`
2. 提取 `content.json` 保存为 `*_测试用例_详细版reviewed_content.json`
3. 检查是否已存在同名文件：
   - 如已存在，更新对应条目和指标
   - 如不存在，执行新入库

### 步骤 6：更新 INDEX.md

- 更新「测试用例库」章节
- 更新知识库统计
- 更新「最后更新」日期

### 步骤 7：更新 EVOLUTION_LOG.md

新增一条进化记录，包含：

- 日期和需求名称
- AI 生成用例数、评审后保留数
- 新增 / 删除 / 修改 / 未变更数量
- 覆盖率、准确率、可执行率等指标
- 关键反思与改进方向

### 步骤 8：呈现入库结果

向用户汇总呈现：

- 差异报告和质量分析报告路径
- 归档文件路径
- 知识库更新状态
- 核心质量指标

---

## 常见错误与预防

| 错误类型 | 表现 | 预防措施 |
|---------|------|---------|
| **跳过对比直接入库** | 缺少差异报告和质量分析报告 | 将两个报告作为入库前置条件 |
| **找不到 reviewed 文件** | 用户未保存 reviewed 版本 | 执行前 glob 检查文件是否存在 |
| **重复入库未更新** | INDEX.md 出现重复条目 | 入库前检查同名文件，存在则更新而非追加 |
| **依赖人工标记** | 提示用户在 XMind 中打标记 | 明确告知用户 AI 自动对比，无需手动标记 |
| **忽略位置调整** | 只对比内容，未识别层级变化 | 对比时同时记录节点路径变化 |

# 测试用例生成全流程 META 文档

> 本文档定义了从 Confluence 需求到测试用例 SVN 归档的完整工作流程
>
> **所有 AI 必须在开始任务前阅读此文档，确保流程完整！**

> **时间追踪（强制）**：会话开始先按 `time-tracking-skill/references/zhj-eight-stage-workflow.md` 完成 MySQL 花名册身份验证和业务线选择；⓪、①、②、③、④、⑤、⑦、⑧每个阶段交付后立即收集并直接保存节省时间。③与④统一累计到一条“生成用例（06）”记录，其他阶段各自一条；保存前不得进入下一步，且不再要求二次确认。
>

## 📋 完整流程（⓪-⑧，含 3 个停止点）

```
┌─────────────────────────────────────────────────────────────┐
│                    测试用例生成全流程                          │
│            （非强制串行，可从任意节点插入）                     │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  Confluence 需求页面 URL                                      │
│              ↓                                               │
│  ⓪ 导出需求 (confluence-requirement-exporter)                │

│              ↓                                               │

│              ↓                                               │
│  ② 需求评审 (md-requirement-review)                          │
│              ↓                                               │
│  ⏸️ 停止点 1：人工确认评审报告                                 │
│              ↓                                               │
│  ③ 详细测试用例生成 (md-to-xmind-testcase)                   │
│              ↓                                               │

│              ↓                                               │

│     提取 P0 → DMP Excel                                      │
│              ↓                                               │
│  ⏸️ 停止点 3：客户确认入库                                    │
│              ↓                                               │
│  ⑤ AI 自动对比与入库 (testcase-archive)                      │
│     直接内容对比，EVOLUTION_LOG 去重                          │
│              ↓                                               │
│  ⑥ 完整性检查                                                │
│              ↓                                               │

│  ⑧ 需求归档 (req-merger)                                     │

└─────────────────────────────────────────────────────────────┘
```

> 💡 **灵活执行原则**：非强制串行，可从任意节点插入执行后续步骤。已有中间产物（如 reviewed XMind）可直接从对应节点开始，前置停止点视为已通过，无需回溯。

## 🔄 步骤详情

### ⓪ 导出需求 (confluence-requirement-exporter)

| 项目 | 内容 |
|------|------|
| **Skill** | `confluence-requirement-exporter` |
| **认证** | 账号密码 Basic Auth（不走 cookie，配置一次永久免密） |
| **首次配置** | 对话输入 `配置confluence：账号=xxx, 密码=yyy` → AI 创建 `~/.workbuddy/confluence_auth.json`（密码 base64 密文） |
| **日常使用** | 对话输入 `新需求：URL` 或 `旧需求：URL` |
| **输入** | Confluence URL + 账号密码（本机配置） |
| **输出** | 新需求→`最新需求/{标题}/{标题}.doc + images/`；旧需求→`原需求/{标题}.doc + 原图片/{标题}.zip` |
| **安全** | 脚本只导出不删除（只读）；密码本机密文存储，不随项目复制泄露 |
| **下一步** | 执行文档转换 |

---

### ① 文档转换 (markitdown-converter)

| 项目 | 内容 |
|------|------|
| **Skill** | `markitdown-converter` |
| **输入** | 需求.doc / 技术方案.doc / PDF / PPT 等原始文档 |
| **输出** | 需求.md / 技术方案.md + images/ |
| **特点** | 无附件时自动清理空 attachments 目录 |
| **下一步** | 执行需求评审 |

---

### ② 需求评审 (md-requirement-review)

| 项目 | 内容 |
|------|------|
| **Skill** | `md-requirement-review` |
| **输入** | 需求.md + 技术方案.md + 图片附件 |
| **输出** | `<文件名>_评审报告.md` |
| **下一步** | ⭐ **停止点 1：等待用户确认评审报告** |

---

### ⏸️ 停止点 1：人工确认评审报告

| 项目 | 内容 |
|------|------|
| **操作** | 生成 `*_评审报告.md` 后，AI 停下 |
| **用户动作** | 审核评审报告中的问题、风险、建议 |
| **确认方式** | 回复"确认"或提出修改意见 |
| **下一步** | 用户确认后，执行详细测试用例生成 |

> 灵活执行：从停止点 1 之后插入时，此停止点视为已通过。

---

### ③ 详细测试用例生成 (md-to-xmind-testcase)

| 项目 | 内容 |
|------|------|
| **Skill** | `md-to-xmind-testcase` |
| **输入** | 需求.md + 评审报告.md + 知识库测试模式/历史用例 |
| **输出** | `<文件名>_测试用例_详细版_v1.0-ai.json` + `.xmind` |
| **说明** | 直接生成详细测试用例（含前置条件、步骤、预期结果、优先级），自我评审补充遗漏 |
| **下一步** | ⭐ **停止点 2：等待用户评审 XMind 用例** |

---

### ⏸️ 停止点 2：人工评审用例

| 项目 | 内容 |
|------|------|
| **操作** | 生成 `*_v1.0-ai.xmind` 后，AI 停下 |
| **用户动作** | 在 XMind 中直接增删改用例（**无需标记颜色**） |
| **保存方式** | 保存为 `*_测试用例_详细版reviewed.xmind`（不带 v1.0） |
| **确认方式** | 回复"已评审" |
| **下一步** | 用户确认后，执行生成冒烟用例 |

> 评审方式：直接增删改，AI 通过用例名+内容对比自动识别差异，无需颜色标记。

---

### ④ 生成冒烟用例 (smoke-testcase-generator)

| 项目 | 内容 |
|------|------|
| **Skill** | `smoke-testcase-generator` |
| **触发** | 用户回复"已评审"后自动执行 |
| **输入** | reviewed XMind + DMP 模板 + 用户故事映射（需求关键词→编码:故事名） |
| **输出** | `testcases/冒烟用例/零售版{版本}/零售版{版本}冒烟用例.xlsx` |
| **特点** | 自动提取 P0 + 按需求分组 + 去多余括号 + 填责任人/编码/故事 |
| **下一步** | ⭐ **停止点 3：客户确认入库** |

---

### ⏸️ 停止点 3：客户确认入库

| 项目 | 内容 |
|------|------|
| **操作** | 生成冒烟用例 Excel 后，AI 停下 |
| **用户动作** | 客户确认冒烟用例无误，同意入库 |
| **确认方式** | 回复"确认入库" |
| **下一步** | 用户确认后，执行 AI 对比入库 |

> 停止点 3 是新增的质量门禁：冒烟用例先交付客户确认，确认无误后才正式入库。

---

### ⑤ AI 自动对比与入库 (testcase-archive)

| 项目 | 内容 |
|------|------|
| **Skill** | `testcase-archive` |
| **触发** | 用户回复"确认入库" |
| **输入** | `*_v1.0-ai.xmind` + `*_reviewed.xmind` |
| **AI 操作** | 直接内容对比（用例名+步骤+预期+优先级），生成差异/质量报告，合并入库 |
| **输出** | 差异报告 + 质量报告 + 更新 testcases/INDEX/EVOLUTION_LOG |
| **去重** | EVOLUTION_LOG 同标题记录替换，不重复追加 |
| **下一步** | 执行完整性检查 |

**对比维度**：

| 维度 | 说明 |
|------|------|
| **新增** | reviewed 有、ai 版无的用例 |
| **删除** | ai 版有、reviewed 无的用例 |
| **修改** | 名称相同但前置/步骤/预期/优先级变化的用例 |
| **未变更** | 名称和内容完全一致的用例 |
| **质量指标** | 场景遗漏率/多余生成率/修改率/通过率/语义准确率 |

> 直接内容对比，无需人工标记颜色。

---

### ⑥ 完整性检查

| 项目 | 内容 |
|------|------|
| **操作** | 检查所有产出物和知识库更新是否完整 |
| **检查项** | 需求MD/评审报告/测试用例/差异报告/质量报告/冒烟用例/INDEX/EVOLUTION_LOG |
| **下一步** | 全部确认后，执行 SVN 归档上传 |

---

### ⑦ SVN 归档上传 (svn-archive)

| 项目 | 内容 |
|------|------|
| **Skill** | `svn-archive` |
| **触发** | 完整性检查通过后；或用户说"上传SVN/归档到SVN" |
| **输入** | ai.xmind + reviewed.xmind + 评审报告.md |
| **输出** | SVN `零售版/v{版本}/` 下 3 个文件 |
| **安全规则** | 只用 `svn mkdir` + `svn import`，**禁止 svn delete** |
| **执行方式** | AI 自动列出文件清单+目标路径并直接执行上传，无需人工确认 |
| **凭据** | svn auth 缓存（免密），不存明文密码 |
| **前置** | 装 SlikSVN + `svn info URL --username xxx --password yyy` 缓存凭据 |
| **下一步** | 执行需求归档 |

> 文件已存在则跳过（不删除重传）。

---

### ⑧ 需求归档 (req-merger)

| 项目 | 内容 |
|------|------|
| **Skill** | `req-merger` |
| **触发** | 项目结束时（所有需求、用例、SVN归档均已完成） |
| **输入** | Confluence 导出的最终需求 `.doc` + 图片 zip |
| **AI 操作** | 解析 MIME `.doc`，提取图片建立 CID 映射，按模块拆分章节 |
| **输出** | `requirements/原需求/<模块>/<模块>_V<版本>_最终需求.md` + images/ |
| **说明** | 项目最终需求基线；同模块同版本覆盖更新 |
| **下一步** | 归档完成后，流程正式结束 |

> 也可在空闲期人工发起整理历史需求（见 QWEN.md "空闲期补充任务"）。

## ⚠️ 强制规则

### 规则 1：开始前必须创建完整 todo list

```
必须包含全部步骤：
⓪ 导出需求
① 文档转换
② 需求评审
③ 详细测试用例生成
④ 生成冒烟用例
⑤ AI 自动对比与入库
⑥ 完整性检查
⑦ SVN 归档上传
⑧ 需求归档

同时必须包含 3 个停止点：
- 停止点 1：人工确认评审报告
- 停止点 2：人工评审用例
- 停止点 3：客户确认入库
```

### 规则 2：AI 在停止点停下等待人工确认

```
- 停止点 1：生成 *_评审报告.md 后停下
- 停止点 2：生成 *_v1.0-ai.xmind 后停下
- 停止点 3：生成冒烟用例 Excel 后停下
- 用户未回复前，AI 不得继续下一步
- 灵活执行：从停止点之后插入时，前置停止点视为已通过
```

### 规则 3：停止点 3 确认后必须执行入库

```
⚠️ 用户回复"确认入库"后，AI 必须执行：
  1. 自动对比 ai 版与 reviewed 版（直接内容对比）
  2. 生成差异报告和质量分析报告
  3. 将 reviewed 版本合并入库
  4. 更新 INDEX.md 和 EVOLUTION_LOG.md（去重替换）
  5. 完整性检查
  6. SVN 归档上传（AI 自动执行）
```

### 规则 4：SVN 上传自动执行 + 只上传不删除

```
⚠️ SVN 归档上传（⑦）规则：
  1. AI 自动列出文件清单 + 目标 SVN 路径
  2. 直接执行上传，无需用户确认
  3. 只用 svn mkdir + svn import，禁止 svn delete
  4. 文件已存在则跳过，不删除重传
```

### 规则 5：灵活执行（非强制串行）

```
- 工作流非强制串行，可从任意节点插入执行后续步骤
- 已有中间产物可直接从对应节点开始（如已有 reviewed XMind 可从④开始）
- 从停止点之后插入时，前置停止点视为已通过，无需回溯
```

## 📝 常见错误与预防

| 错误类型 | 表现 | 预防措施 |
|---------|------|---------|
| **跳过停止点** | 评审/用例/冒烟未确认就继续 | 生成产物后 AI 必须停下，等用户回复 |
| **遗漏冒烟用例** | ⏸停2 后直接入库，跳过④ | ⏸停2 后必须先执行④冒烟用例→⏸停3 |
| **SVN 未列清单就上传** | ⑦ 没列清单直接 svn import | AI 自动列出文件清单+目标路径后执行上传 |
| **SVN 执行 delete** | 用 svn delete 覆盖文件 | 只用 mkdir+import，禁止 delete，已存在则跳过 |
| **依赖 cookie** | 还在用过期 cookie 导出 | 改用账号密码 Basic Auth，配置一次永久免密 |
| **要求颜色标记** | 要求用户在 XMind 标记颜色 | 直接增删改，AI 内容对比识别差异 |
| **EVOLUTION_LOG 重复** | 重新入库时追加重复记录 | 同标题记录替换，不重复追加 |
| **强制串行** | 不允许从中间节点插入 | 灵活执行，可从任意节点插入 |

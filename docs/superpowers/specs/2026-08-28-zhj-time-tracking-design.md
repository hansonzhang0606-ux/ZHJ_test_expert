# 智慧记运营测试套件时间追踪设计

## 目标

将时间追踪嵌入智慧记运营测试套件的八个实际 Skill，记录测试人员在每个阶段节省的工时，并同步到现有公共 MySQL 数据库。

## 会话与业务线

会话先读取 MySQL `agent_team_roster` 验证员工身份。单业务线成员自动选择其唯一业务线；多业务线成员以编号选择本次业务线。选择结果只在会话内缓存，并作为全部时间记录的 `biz_line` 与 `biz_line_code`，不将业务线写死为 ZHJ。

## 时间记录

每个阶段交付后必须立即收集员工输入的节省时间；输入后直接保存，不再二次确认。拒绝输入最多追问两次，此后保存 0 小时且备注为“用户未反馈”。

| 工作流 | 记录名称 | 编码 | 记录规则 |
|---|---|---|---|
| ⓪ 导出需求 | 导出需求 | 00 | 单条 |
| ① 转 MD | 文档整理 | 01 | 单条 |
| ② 需求评审 | 需求评审 | 02 | 单条 |
| ③ 生成测试用例 | 生成用例 | 06 | 与④合并 |
| ④ 生成冒烟用例 | 生成用例 | 06 | 累加更新③的同一条记录 |
| ⑤ AI 对比入库 | AI 对比入库 | 05 | 单条 |
| ⑦ SVN 归档上传 | SVN 归档上传 | 08 | 单条 |
| ⑧ 需求归档 | 入库知识库 | 07 | 单条 |

合并键为当前会话、业务线、员工、用户故事与步骤编码。③首次反馈创建记录；④反馈将 `time_saved_hours`、`time_saved_pd`、`total_hours` 累加进该条记录，并保留③的记录时间作为 MySQL 幂等键依据。

## 持久化与同步

原始数据保存在 `~/.workbuddy/data/time-tracking/{biz_line}/records.jsonl`。每台电脑的 MySQL 配置独立生成且不参与打包。定时任务在业务线确认后幂等注册至每日 09:00、12:00、18:00，同步至公共 `agent_time_tracking` 表。

## 交付

输出一个 IDE 套件 ZIP 与一个 WorkBuddy 专家 ZIP。二者共享完全相同的时间追踪脚本和八步规则；WorkBuddy 包额外含专家入口、市场清单与注册脚本。

> 适用对象：智慧记测试团队成员（功能测试）

> 代码仓库：`https://github.com/hansonzhang0606-ux/ZHJ_test_expert`（分支 `main`）

本指南说明两件事：

1. **在本地电脑的 WorkBuddy 中安装「智慧记测试专家」专家包**（开箱即用，含八阶段工作流 + 身份/业务线校验 + 工时追踪）。

## 1. 在本地 WorkBuddy 中安装专家

### 1.1 前置条件

- 已安装并登录 **WorkBuddy**（桌面端或对应客户端）。
- 能访问 GitHub（公司网络可正常打开 `github.com`）。
- 你本人已在管理员的 MySQL `agent_team_roster` 花名册中（否则专家会拒绝服务，需联系管理员添加）。

### 1.2 安装步骤（从 GitHub 导入专家）

> 专家包位于仓库的 **`workbuddy/zhj-testing-expert/`** 子目录（内含 `.codebuddy-plugin/plugin.json`，这是 WorkBuddy 识别专家的关键文件）。仓库根本身**不**含该文件。

**方式 A：从 Git 仓库 URL 直接导入（推荐先试）**

1. 打开 WorkBuddy，进入 **专家中心 / 自定义专家**（左侧栏「专家」入口）。
2. 选择 **从 Git 仓库导入 / 添加自定义专家**，粘贴仓库地址：
   ```
   https://github.com/hansonzhang0606-ux/ZHJ_test_expert
   ```
3. 确认后，WorkBuddy 会扫描仓库并定位含 `plugin.json` 的 `workbuddy/zhj-testing-expert/` 目录，
   列出专家 **「智慧记测试专家」（ZHJ Testing Expert）**。
4. 点击 **安装 / 信任**，等待下载完成（头像、agent、skills 一并装入）。
5. 安装完成后，在专家列表即可看到「智慧记测试专家」及其头像（新版 PNG）。

**方式 B：从本地目录导入（当方式 A 未自动识别子目录时兜底，最稳妥）**

若方式 A 导入后未列出专家（个别版本只扫描仓库根），改用本地目录导入：
1. 先把仓库克隆到本地：
   ```bash
   git clone https://github.com/hansonzhang0606-ux/ZHJ_test_expert.git
   ```
2. 在 WorkBuddy 专家中心选择 **从本地目录导入 / 添加本地专家**，
   选择克隆下来的 `ZHJ_test_expert/workbuddy/zhj-testing-expert/` 文件夹（即包含 `.codebuddy-plugin` 的那一层）。
3. 点击 **安装 / 信任** 即可。

> 若列表仍显示旧头像，重启 WorkBuddy 或在专家列表刷新/重新加载该专家即可。

### 1.3 验证安装

1. 新建一个与该专家的会话，首条消息专家会要求：**输入姓名完成身份验证**，并从以下四条业务线中选择本次获授权的一条：
   - 智慧记+运营系统（ZHJ）
   - 智慧记零售（ZHJLS）
   - AI进销存（AIJXC）
   - 国际版Ailit（AILIT）
2. 输入你的姓名 → 选择业务线编号 → 专家校验通过后即可开始八阶段测试工作流。
3. 若提示「不在花名册 / 业务线无权」，联系管理员在 `agent_team_roster` 表维护你的记录。

### 1.4 更新专家（拉取新版本）

仓库更新后（如头像、工作流、skill 调整），在专家中心对该专家执行 **更新 / 重新拉取** 即可覆盖到最新版。无需手动下载 zip。

## 2. 在本地 VSCode 中使用 Skill 套件

> 场景说明：如果你日常在 VSCode 里用 AI 编程助手（Claude Code / OpenCode / 通义灵码 Qwen Code / Cline 等）做测试工作，
> 可以直接把 `ZHJ_test_skills` 这套 Skill 挂到该助手的 skills 目录里使用。**脚本层与宿主无关**，
> 工时数据最终同样汇总到团队共享 MySQL 表 `agent_time_tracking`。

### 2.1 前提：需要一个支持 "skills" 的 AI 编程助手

下列任一 VSCode 扩展/工具均可（它们都能读取本地 `skills/<name>/SKILL.md`）：

| 工具 | 在 VSCode 中的形态 | skills 目录（放置点见 2.3） |
|------|-------------------|------------------------------|
| **通义灵码 / Qwen Code** | 扩展或 CLI | 项目/用户级 `.qwen/skills/` |
| **Claude Code** | VSCode 扩展 | `~/.claude/skills/` 或项目 `.claude/skills/` |
| **OpenCode** | VSCode 扩展 / CLI | `~/.config/opencode/skills/` 或项目 `.opencode/skills/` |
| **Cline / Continue** | VSCode 扩展 | 各自 skills 配置目录 |

> 本套件原始文档中引用路径为 `.qwen/skills/...`，因此**通义灵码 / Qwen Code 是最贴合的默认选择**，但步骤对所有支持 skills 的助手通用。

### 2.2 环境准备（Python 依赖）

套件脚本需要 **Python 3.8+**（建议 3.10+）。一次性安装：

```bash
pip install "markitdown[all]" pywin32 beautifulsoup4 openpyxl cryptography
```

| 依赖 | 用途 | 备注 |
|------|------|------|
| `markitdown[all]` | ① 转 MD（Word/PDF/PPT/Excel → MD） | 核心 |
| `pywin32` | ① 转 MD 在 Windows 下的 COM 支持 | **仅 Windows**；macOS/Linux 可省略（部分格式受限） |
| `beautifulsoup4` | ⑧ 解析 Confluence MIME `.doc` | 核心 |
| `openpyxl` | ④ 冒烟用例 Excel 生成 | 核心 |
| `cryptography` | 连接 **MySQL 8.0+**（`caching_sha2_password` 认证）时加密支持 | **推荐安装**；团队 MySQL 若为 8.0+ 且非 SSL 连接则**必须**，否则连接报错 |
| `PyYAML` | 配置文件解析 | 套件有简易兜底，可缺省 |
| `pymysql` | MySQL 工时同步 | **已打包**在 `time-tracking-skill/scripts/pymysql/`，无需安装（该包内部按需调用 `cryptography`） |

### 2.3 部署步骤

1. **克隆仓库**（或下载 zip 解压）：
   ```bash
   git clone https://github.com/hansonzhang0606-ux/ZHJ_test_expert.git
   ```
2. **定位套件目录**：仓库内有**两份内容一致**的套件，用任一即可（推荐根目录那份，路径更短）：
   - 推荐：`ZHJ_test_expert/ZHJ_test_skills/`（仓库根直接放置）
   - 备选：`ZHJ_test_expert/workbuddy/zhj-testing-expert/skills/ZHJ_test_skills/`（专家包内嵌那份）
3. **把 `ZHJ_test_skills` 整个文件夹拷到你所用助手的 skills 目录**（参考 2.1 表格）：
   - 通义灵码 / Qwen Code：`<你的项目>/.qwen/skills/ZHJ_test_skills/`
   - Claude Code：`~/.claude/skills/ZHJ_test_skills/`（全局）或 `<项目>/.claude/skills/ZHJ_test_skills/`
   - OpenCode：`~/.config/opencode/skills/ZHJ_test_skills/`
4. **（可选）在 VSCode 中打开仓库目录**作为工作区，让助手在该项目上下文里调用 Skill。
5. 启动对应 AI 助手，**让它读取 `ZHJ_test_skills/SKILL.md` 与 `META_WORKFLOW.md`**，即可按八阶段工作流执行。

> 复制时请保留 `ZHJ_test_skills` 这一层目录名，使其与 `SKILL.md` 中的 `name: zhj-test-skills` 对应，便于助手识别。

### 2.4 使用流程（八阶段工作流）

开启会话后，先让助手**阅读 `META_WORKFLOW.md`**，再按顺序推进（可在任意节点插入）：

```
⓪ 导出需求 → ① 转 MD → ② 需求评审 → ⏸️人工评审
→ ③ 生成测试用例 → ⏸️人工评审XMind
→ ④ 生成冒烟用例 → ⏸️客户确认入库
→ ⑤ AI 对比入库 → ⑦ SVN 归档上传 → ⑧ 需求归档
```

每个阶段由对应 Skill 驱动（详见套件内 `8个Skill阶段映射表.md`）：

| # | 阶段 | 对应 Skill |
|---|------|-----------|
| ⓪ | 导出需求 | `confluence-requirement-exporter` |
| ① | 转 MD | `markitdown-converter` |
| ② | 需求评审 | `md-requirement-review` |
| ③ | 生成测试用例 | `md-to-xmind-testcase` |
| ④ | 生成冒烟用例 | `smoke-testcase-generator` |
| ⑤ | AI 对比入库 | `testcase-archive` |
| ⑦ | SVN 归档上传 | `svn-archive` |
| ⑧ | 需求归档 | `req-merger` |
| — | 工时追踪（跨阶段） | `time-tracking-skill` |

### 2.5 身份与业务线验证（MySQL 花名册）

无论 WorkBuddy 还是 VSCode，套件都会**先通过 MySQL `agent_team_roster` 校验姓名与业务线归属**，校验不通过不写数据。

- 首次使用，身份验证通过后助手会自动检测本机 `mysql_config.json`；不存在会提示输入数据库密码并自动生成。
- 多业务线成员会被要求**输入编号**选择本次业务线（避免自由文本匹配不准）。
- 你本人不在花名册或所选业务线无权 → 联系管理员执行：
  ```sql
  INSERT INTO agent_team_roster (biz_line, name, role, active) VALUES
    ('智慧记+运营系统', '你的姓名', '功能测试', 1);
  ```

### 2.6 时间节省追踪（MySQL 配置，可选但推荐）

工时数据默认写本地 JSONL，再由定时任务（每日 09:00 / 12:00 / 18:00）同步到团队共享 MySQL。

> 以下命令请在**仓库根目录 `ZHJ_test_expert/`** 下执行（根目录已含 `ZHJ_test_skills/`）。

```bash
# 初始化本机 MySQL 配置（首次）
python ZHJ_test_skills/time-tracking-skill/scripts/init_mysql_config.py --biz-line "智慧记+运营系统"

# 生成 HTML 工时报告（助手在 IDE 回复中给出文件路径，浏览器打开）
python ZHJ_test_skills/time-tracking-skill/scripts/generate_time_analytics.py --biz-line "智慧记+运营系统"
```

> 不初始化 = 数据只在本机 JSONL，管理员在数据库看不到你；记录功能本身不受影响。

## 3. 常见问题 / 排错

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| WorkBuddy 列表头像是旧的 | 内嵌缓存未刷新 | 重启 WorkBuddy 或重新加载该专家 |
| 从 Git URL 导入后**未列出专家** | 个别版本仅扫描仓库根，未识别 `workbuddy/zhj-testing-expert/` 子目录 | 改用 1.2 **方式 B**：克隆后用「从本地目录导入」选该子文件夹 |
| 专家拒绝服务：「不在花名册」 | MySQL `agent_team_roster` 无你的记录 | 联系管理员 INSERT 你的姓名+业务线 |
| VSCode 中助手不识别 Skill | 没放到正确的 skills 目录 / 目录名不符 | 检查 2.1 表格中的 skills 放置点，保留 `ZHJ_test_skills` 目录名 |
| ① 转 MD 失败（Windows） | 缺 `pywin32` 或 Word 未安装 | `pip install pywin32`；确认本机有 Microsoft Word |
| ④ 冒烟用例生成失败 | 缺 `openpyxl` | `pip install openpyxl` |
| 连接 MySQL 8.0+ 失败 / 报 `cryptography` 缺失 | 缺 `cryptography`（`caching_sha2_password` 认证需要） | `pip install cryptography` |
| 工时不同步到数据库 | 未初始化 MySQL 配置 | 运行 `init_mysql_config.py`；或手动 `sync_to_mysql.py` |
| 从 GitHub 拉取/导入失败 | 网络或仓库权限 | 确认能访问 `github.com/hansonzhang0606-ux/ZHJ_test_expert` |
| 自行运行 `build_workbuddy_package.py` 报 `zhj-testing-expert.svg` missing | 脚本校验项未随头像 PNG 化更新（仓库已是 `.png`） | 普通安装**无需**运行该脚本；如确需构建，把该校验项 `.svg` 改为 `.png` 即可 |
